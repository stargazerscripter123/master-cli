# master-cli：功能表达与部署文档审查

审查日期：2026-11-12。代码基线：`ac599fa`，本次修改集中在 README、相关手册与配置忽略规则。

本报告的测试记录对应最初的文档审查。后续 Antigravity Linux 适配与真实查询验证已单独提交为 `59407be`；README 展示调整则纳入本次文档提交。

## 结论

工具的主要价值是把混合 GPU 机群、单机系统诊断、热状态和 AI 多账号配额放进同一套终端工作流。原 README 主要罗列工具与展示截图，没有充分解释这些能力如何帮助用户安排任务、定位瓶颈和使用已有订阅；从新环境开始部署的步骤也不完整。

新版英文与繁体中文 README 在第一行互相链接，按「用途与优势 → 安装验证 → 机群部署 → AI 账号 → 导出整合 → 排错」组织。保留总览图，其余截图折叠展示。功能说明依据当前实现，示意硬件与订阅标签不再承担兼容性或性能证明的作用。

| SSH 并行采样、连接复用与失败退避 | 方便部署和处理不可达节点 | [transport.py](../src/gpumaster/transport.py)、[thermalmaster/app.py](../src/thermalmaster/app.py) 的 `HostLink` |

## 发现与处理

| 优先级 | 原有问题 | 处理结果 |
|---|---|---|
| P1 | README 笼统声称远端不需安装，掩盖 `macmaster --fleet` 的要求 | 将三种机群部署分别说明。`gpumaster` 远端运行 Bash；温度机群运行串流 Python；系统机群需要已安装的 `macmaster`。依据：[FleetCollector](../src/macmaster/collectors/fleet.py)。 |
| P1 | 两种语言的 tokenmaster 手册使用不支持的 `history --by …` | 改成实际支持的 `history daily/models/projects` 与 `-p`，并核对参数解析及有效历史视图。 |
| P1 | 手册声称状态栏总是不阻塞、过期后自动后台刷新 | 按 `cmd_statusline` 的实际分支说明默认同步刷新、`--async-refresh` 与 `--no-refresh`，补充首次快照要求。 |
| P1 | 配置目录不可写时会退到当前目录 `.tokenmaster/`，原 gitignore 未覆盖 | 为本仓库增加 `.tokenmaster/` 忽略规则，并说明该规则不保护其他仓库；记录 `TOKENMASTER_CONFIG_DIR` 的固定目录选项。未改变配置写入行为。 |
| P2 | 安装从「在此目录执行」开始，缺少克隆、PATH、验证及路径生命周期 | 补充完整步骤、shell PATH、虚拟环境、源目录不可随意移动、更新和移除。 |
| P2 | 隐藏了任务选择、统一内存、多账号、历史与导出等关键能力 | 用具体任务解释每项优势，并给出可解析的示例命令。 |
| P2 | tokenmaster 手册提到未实现的 `TOKENMASTER_DEADLINE` 环境变量 | 改成代码实际读取的 `deadline_seconds` 配置；说明默认值和 `0` 的含义。 |
| P2 | `smart` 被简化成只选「剩余最多」；`pick` 输出格式说明错误 | 说明配额、短视窗和重设时间的考虑因素，以及仅输出账号名需要 `--quiet`。 |
| P2 | Apple GPU 的温度、功耗与逐进程能力边界不清楚 | 区分基础内建命令采样、可选 `macmon` 丰富字段和 `macmaster` 自己的原生采集路径。 |
| P2 | 截图中的具体硬件和方案容易被理解成已实测支持 | 总览、机群与订阅画面标记为示意数据；Mac 单机截图另行说明硬件。README 单机图仅保留 Mac，机群图继续保留。 |
| P2 | HTTP 部署未说明无内建认证和 TLS | 保留 loopback 示例，说明数据范围与 SSH tunnel 访问方法。 |
| P2 | 原说明绝对化表示凭证不会进入仓库、只读取既有登录 | 说明认证、快照和刷新可能保存或复制凭证，以及配置和 profile 的实际位置。 |
